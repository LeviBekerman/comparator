# פנקס — License Server

שרת קטן ומינימלי שעושה דבר אחד: מאמת מפתח רישיון מול Gumroad ומחזיר `{valid, plan}`.
הוא לא רואה ולא שומר שום נתון הנהלת חשבונות — רק מפתחות רישיון ומזהי מכשיר.
פנקס עצמו נשאר עובד אופליין; רק פעולת האימות (חד-פעמית, ואז מדי כמה שבועות ברקע) פונה לשרת הזה.

## למה Cloudflare Workers?

חינמי (עד 100,000 בקשות ביום), קנה מידה אוטומטי, בלי שרת לתחזק.

## שלב 1: הגדרת מוצר ב-Gumroad

1. פתחו חשבון ב-[gumroad.com](https://gumroad.com) ויצרו מוצר (המחיר/תיאור לבחירתכם).
2. בהגדרות המוצר, הפעילו **"Generate a unique license key per sale"** — Gumroad ייצר ויישלח מפתח רישיון אוטומטית לכל קונה, בלי שתצטרכו לבנות מנגנון הפצה בעצמכם.
3. זהו — אין צורך ביצירת Application או access token. כל מה שצריך הוא ה-**permalink**, שהוא פשוט הסיומת בכתובת הציבורית של עמוד המוצר שלכם: `gumroad.com/l/<permalink>`.

## שלב 2: פריסת השרת

```bash
npm install -g wrangler
wrangler login          # מתחבר לחשבון Cloudflare שלכם (חינמי)
cd license-server
wrangler kv namespace create LICENSES     # אופציונלי אך מומלץ - ראו הסבר למטה
```

עדכנו את `wrangler.toml`:
- `GUMROAD_PRODUCT_PERMALINK` — ה-permalink משלב 1 (כבר ממולא לפנקס עם `yhyhhwe`).
- אם יצרתם KV namespace — הסירו את ה-`#` משלוש השורות התחתונות והדביקו את ה-`id` שקיבלתם.
- `ALLOWED_ORIGIN` — כתובת האתר בו יתארח `pinkas.html` (או `*` בזמן בדיקות).

```bash
wrangler deploy
```

תקבלו כתובת כמו `https://pinkas-license-server.YOURNAME.workers.dev`.

## שלב 3: חיבור ל-pinkas.html

פתחו את `pinkas.html`, חפשו את הקבוע `LICENSE_SERVER_URL` בתחילת ה-`<script>`, והדביקו את הכתובת שקיבלתם.

## מה ה-KV namespace עושה בפועל?

זהו קאש: אם Gumroad זמנית לא זמין, השרת עדיין יכול להחזיר את התוצאה התקפה האחרונה שראה עבור אותו מפתח (עד 30 יום), כדי שרכישה תקפה לא תיחסם רק בגלל תקלה זמנית אצל Gumroad. זה אופציונלי — בלעדיו, תקלה אצל Gumroad פשוט תיכשל (ותחזור לעבוד ברגע ש-Gumroad חוזר).

## איך זה מתנהג בפועל

- לקוח מזין מפתח פעם אחת ("הפעלה") → השרת בודק מול Gumroad ומגדיל את מונה השימושים.
- מפנקס נשמרת התוצאה מקומית (localStorage) ומופעלת התכונה בתשלום.
- כל כמה שבועות פנקס בודק שוב ברקע (בלי לחסום שימוש) כדי לתפוס החזר כספי/ביטול.
- אם אין אינטרנט — פנקס ממשיך לעבוד עם התוצאה האחרונה הידועה (לא נועל משתמש משלם רק כי הוא לא מחובר).
- `MAX_ACTIVATIONS` מגביל כמה מכשירים/דפדפנים יכולים להפעיל את אותו מפתח.

## החלפת ספק תשלומים

לא חייבים Gumroad — כל שירות עם API דומה (Lemon Squeezy, Paddle) יעבוד אם תחליפו את הפונקציה `handleVerify` ב-`worker.js` בקריאה המתאימה. שאר האפליקציה (הקאש, ה-UI, ה-gating) לא צריכים להשתנות.
